## 4. 공통 골격 (10/5 첫 PR로 먼저 머지)

두 사람이 같은 파일을 동시에 만들면 충돌이 나므로, **리원이 첫 PR에서 아래 골격을 만들고 dev에 먼저 머지**합니다. 제민은 그 뒤에 dev를 받아서 시작합니다.

```
src/
├── app/diaries/                  # 라우트 (화면 파일은 여기에만)
│   ├── _layout.tsx
│   └── ...
└── features/diaries/
    ├── api/
    │   └── query-keys.ts         # 일기·공유방·댓글 query key 팩토리 (한 곳에서 관리)
    ├── components/
    ├── hooks/
    ├── types/
    └── utils/                    # 정렬, 날짜 표시 등 순수 함수
```

- 라우트 경로(`src/app/diaries/...`)는 딥링크·푸시 알림 경로가 되므로, 한 번 정하면 바꾸지 않습니다 (AGENTS.md §13)
- 공유방을 별도 feature(`src/features/rooms/`)로 뺄지는 첫 PR 전에 둘이 정합니다

## 5. 브랜치 / PR 규칙

- 모든 브랜치는 `dev`에서 분기하고, PR도 `dev`로 보냅니다
- 브랜치: `feat/LUV-<번호>`, 커밋: `feat(LUV-<번호>) :: 요약` (`CONTRIBUTING.md`)
- 화면 단위로 PR을 작게 나눕니다 — 10/13 크로스체크 때 리뷰하기 쉽도록
- `openapi.json` 갱신은 기능 브랜치에 섞지 말고 `chore/LUV-<번호>`로 따로 PR
- 패키지 매니저는 **pnpm만** 사용 — `package-lock.json`이 생기면 커밋하지 말고 삭제

## 7. 작업전 pnpm 설치
1. pnpm설치
   ```
   npm install -g pnpm
   ```
2. npm이 만든 파일 삭제(npm으로 잘못 설치했으면)
   ```
   rm -rf node_modules package-lock.json
   ```
3. pnpm으로 다시 설치
   ```
   pnpm install
   ```

npm install -g에서 권한 에러(EACCES)가 나면 sudo 없이 이 명령으로 대신하세요.
```
curl -fsSL https://get.pnpm.io/install.sh | sh -
```
