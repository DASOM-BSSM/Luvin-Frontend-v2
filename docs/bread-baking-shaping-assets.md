# LUV-88 빵굽기 개편: 필요한 이미지 (성형 · 오븐)

작성: 2026-10-29 (Asia/Seoul). 상태: **디자인 요청 전 초안**. 성형·오븐 결정 대부분 확정, 각 단계의 "남은 질문"만 남았다.

# 1. 성형 단계

## 바꾸려는 방식

레퍼런스: 사용자가 공유한 화면 녹화(쥬니버 "쟈스민의 김밥만들기"). 영상 파일은 레포에 없다.

- 레퍼런스 흐름: 김발이 화면 아래를 크게 차지 → 가운데 밥 → 화살표(←, →, ↖ …)가 하나씩 뜸 → 그 방향으로 문지르면 밥이 넓어짐 → 김발을 다 채우면 완료.
- 소금빵 적용 (사용자 확정, 2026-10-29): **큰 도마를 펼침 → 반죽을 올림 → 밀대로 반죽을 폄 → 버터를 넣음 → 화살표 방향대로 문질러 성형(5번) → 소금을 넣음 → 다음 단계(오븐).**
- 현재 구현(`baking-shaping-scene.tsx`)과의 차이: 지금은 작은 도마 위에서 밀대 문지르기 → 버터 드래그 → 반죽 자체를 잡고 문지르기다. 성형 결과(`shapedBread` 슬롯)는 정의만 되어 있고 화면에 나오지 않는다. 소금은 장식이다.

## 확정 사항 (사용자 결정, 2026-10-29)

1. **밀대 단계 유지**: 큰 도마 위에서 밀대로 반죽을 편다. 그 뒤에 버터를 넣는다.
2. **버터 시점**: 밀대로 반죽을 편 **다음**, 성형 **전**에 넣는다.
3. **화살표 성형**: 화살표가 **5번** 나온다. 5번 중 **3번 이상 틀리면 성형 실패**. 실패해도 빵을 버리지 않는다(기회 소실 없음) — 알림 후 화살표 성형을 처음부터 다시 한다.
4. **소금 단계**: 성형을 마친 **뒤**에 소금을 넣는다(Figma `7966:6180`에 있던 소금통을 이 단계에서 쓴다).
5. **완료 연출 없음**: 성형(그리고 소금)이 끝나면 별도 연출 없이 다음 단계로 넘어간다. 레퍼런스의 "good job + 점수"는 넣지 않는다.

### 이미지 수를 줄이는 방향 (채택)

- 레퍼런스는 문지른 **방향마다** 밥이 그쪽으로 뻗는 그림이 따로 있다. 이 방식이면 이미지가 방향 수 × 단계 수만큼 늘어난다.
- 대신 **방향과 상관없이, 맞게 문지를 때마다 다음 단계 그림으로 교체**한다. 4번의 2~3장으로 끝난다.

## 구현 메모

- 밀대·버터·소금 조작은 지금 방식(손가락 기준 판정, 작업 영역 안 이동 거리 충족 시 바로 진행)을 그대로 쓴다. 소금은 다른 재료처럼 반죽 위로 끌어다 놓는다.
- 화살표 판정: 화살표 하나당 한 번의 스와이프로 판정하고(맞음/틀림), 맞든 틀리든 다음 화살표로 넘어간다. 5개가 끝났을 때 틀린 횟수가 3 이상이면 실패. 틀린 횟수가 3이 되는 순간 바로 실패 처리해도 결과는 같다(남은 화살표로 만회 불가).
- 화살표 방향 순서 생성·스와이프 방향 판정은 순수 함수로(`src/features/bread-baking/utils/`), 난수는 인자로 받는다. 대각선 포함 여부와 판정 각도 허용 범위는 구현에서 정하고 플레이 후 조정한다.
- 성형 실패 = 기회 소실 없음(사용자 결정): 반죽·버터는 그대로 두고 화살표 5개를 새로 뽑아 성형만 다시 한다. 밀대·버터 단계로 되돌아가지 않는다.

## 성형 실패 알림 (사용자 확정, 2026-10-29)

- Figma `모달` **`7958:5971`** 형식의 NOTICE 쪽지로 알린다: 회색 딤 배경 + 흰 쪽지(342×121) + 분홍 `NOTICE` 제목(Ok Mallang B) + 안내 문구 한 줄. **버튼이 없다.**
- 문구 (확정): "**방향에 맞춰서 드래그해주세요!**"
- 새 이미지는 필요 없다. 기존 `ConfirmModal`(`src/components/ui/confirm-modal.tsx`)·`InfernoNoticeModal`과 같은 쪽지 스타일인데 둘 다 버튼이 있으므로, 버튼 없는 변형을 만든다.
- **닫기: 화면 아무 곳이나 탭하면 닫힌다.** 닫히면 화살표 성형을 처음부터 다시 한다(빵은 유지).
- **알림이 떠 있는 동안 게임 시간은 멈춘다**(설명·나가기 모달과 같은 방식: `useBakingGame`의 `isRunning` 조건에 포함).
- 참고: 같은 시안의 원래 문구는 "밀어낸 반죽에 버터를 넣어야해요!"다. 디자인 쪽에 순서를 틀렸을 때 안내하는 의도가 있었을 수 있다. 지금 구현은 순서가 틀린 입력을 조용히 무시한다. 요청받지 않았으므로 추가하지 않았다.

# 2. 오븐 단계

## 바꾸려는 방식 (사용자 결정, 2026-10-29)

- **타이머 하나를 우리 디자인으로 새로 만든다.** 타이머 안에 빨강·주황·초록 구간을 둔다.
- **구간은 시도(빵 하나)마다 달라진다** → 구간 위치·폭은 코드로 생성하고 코드로 칠한다. 이미지로 받지 않는다.
- **반죽을 오븐에 넣으면 트레이 위 반죽이 사라진다.** 굽는 동안 오븐 안에 빵을 그리지 않는다. 꺼낸 결과는 트레이 위에 나타난다.
- **오븐 디자인은 고치지 않는다.** 기존 `oven.png` / `lit-oven.png` 그대로 쓴다.
- 위 변경(빵 숨기기·결과를 트레이에 표시)은 **타이머 개편 때 한꺼번에 구현한다.** 지금 코드(박자 점멸, 탄 빵을 오븐 안에 표시)는 개편 전 임시 상태다.

## 새로 필요한 이미지

| # | 이미지 | 설명 |
|---|---|---|
| 1 | 타이머 본체 (틀) | 테두리·배경. 사용자가 GPT 이미지 생성으로 만든다. 안쪽 색 구간은 코드로 그리므로, **구간이 들어갈 안쪽 영역은 비워 둔** 틀이어야 한다. 바늘이 지나가는 시작점·끝점이 어디인지도 함께 알려 주면 코드 좌표를 맞추기 쉽다. |
| 2 | 현재 위치 표시 (바늘·마커) | 시간이 흐르며 타이머 위를 움직이는 표시. 틀과 분리된 이미지여야 코드에서 움직일 수 있다. |

## 이미지가 아니라 코드/토큰으로 처리하는 것

- **구간 색**: Figma `Color system`에 `state color/error #FF0030`(빨강), `state color/warning #FFBA00`(주황), `state color/success #00D55B`(초록)이 이미 있다(`src/constants/colors.ts`의 `state`). 이 색을 쓸지, 타이머 전용 색을 받을지 디자이너에게 확인한다.
- **구간 위치·폭**: 시도마다 생성하는 순수 함수(`src/features/bread-baking/utils/`), 난수는 인자로 받는다.

## 확정 사항 (사용자 결정, 2026-10-29)

1. **타이머 모양**: 디자인을 따른다. 타이머 이미지는 사용자가 GPT(이미지 생성)로 만든다. 코드는 받은 모양에 맞춰 구간 그리기 방식을 정한다(가로 막대면 flex 구간, 원형/반원이면 호 그리기 — 이미지가 오면 결정). 그러려면 위 "새로 필요한 이미지" 1번처럼 **구간이 들어갈 안쪽은 비워 둔** 틀이어야 한다.
2. **꺼내는 입력**: **오븐을 탭(클릭)**. 드래그로 꺼내기는 없앤다. 별도 버튼은 두지 않으므로 버튼 이미지는 필요 없다.
3. **색 의미**: 초록 = 제때. 주황 = 살짝 덜 익음(초록 앞) / 살짝 오버쿡(초록 뒤). 빨강 = 많이 덜 익음 / 탐. **주황은 사실상 디자인(초록→빨강 사이 단계 표현)을 위한 구간**이다.
4. **시도마다 바뀌는 것**: 꺼내야 할 때, 즉 구간 위치. **초록 위치가 바뀌고, 주황·빨강은 초록을 기준으로 배치**한다(`빨강 | 주황 | 초록 | 주황 | 빨강`). 폭·속도·난이도 곡선은 구현 쪽에서 정한다(아래 구현 메모).
5. **기존 박자 연출**: 없앤다(1~3박 번쩍임, 4박 점등, `isOvenLit`, `pulseMs`).
6. **시간 초과**: 끝까지 꺼내지 않으면 **탄 빵 이미지를 그냥 보여 준다**(트레이 위).
7. **불 켜진 오븐**: 반죽을 넣는 순간부터 꺼낼 때(탭 또는 시간 초과)까지 `lit-oven`을 보여 준다. 그 외에는 `oven`.

## 구현 메모 (이미지 도착 후)

- 구간 생성은 순수 함수로: 입력 = 난수, 출력 = 초록 시작·끝(0~1 비율). 주황은 초록 양옆에 고정 폭, 나머지는 빨강. 초록 위치는 주황이 타이머 밖으로 넘치지 않는 범위에서 고른다. 고정 폭 값들은 `BAKING_RULES`에 둔다(초기값, 플레이 후 조정).
- 판정 (사용자 확정): 탭한 순간 바늘 위치가
  - 초록 → 성공(`baked`, `baked-bread`)
  - 초록 **앞** 주황·빨강 → 실패, 덜 익음(`raw`, `salt-bread`)
  - 초록 **뒤** 주황·빨강 → 실패, 탐(`burnt`, `burnt-bread`)
  - 끝까지 탭하지 않음 → 실패, 탐(`burnt`)
  - 주황은 실패로 처리한다(성공 인정 없음). 지금 reducer의 `ovenResult`(`baked`/`raw`/`burnt`)를 그대로 쓸 수 있다.
